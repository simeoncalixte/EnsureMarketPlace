Delivery structure

AIN is the project of record. Thirteen epics organize completion and data-model improvements. The finance audit added 34 child tickets: 11 Bugs and 23 Tasks labeled gap. AIN-47 adds eight data-model implementation Tasks. Existing issue parents were retained and cross-cutting schema work is linked through relationships.

Prioritization

P0/P1 values in descriptions and labels are planning priorities, not estimates or promised release dates. Fix pricing-input correctness and payment/plan authorization issues alongside the party/currency/revision foundation. Work on complete evidence-backed journeys rather than treating the existence of a page or model as completion.

Required evidence for Done

  • A concrete user-visible outcome and approved data/financial semantics.
  • Meaningful tests at the responsible service boundary, including negative authorization and failure cases.
  • Migration and compatibility proof for persisted-model changes.
  • Source/build versions and linked reviewer evidence.
  • Known limitations, operational recovery behavior and documentation updates.

Documentation maintenance

Update the owning Confluence child page when behavior changes, link the delivery ticket and name the verification performed. Keep observed findings separate from proposed design. Mark stale historical documents explicitly; never use a past “complete” summary to infer current production readiness.
