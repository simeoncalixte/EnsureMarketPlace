Configuration boundaries

AreaOperational contract
Identity/gatewayConfigure public origin and request-signing secrets for the selected topology. Combined Worker and separate Node deployments have different requirements; follow the Auth guide.
DatabaseService-local database URL/credentials; shared local server does not grant permission to read another service’s private schema.
EmailConnector secret and registry discovery; outbound provider/sender settings. Provider acceptance is not inbox delivery.
KYC / Network / FeedbackDistinct service secrets, scopes and URLs. Do not expose trusted internal data endpoints directly to browsers.
Private packagesProvide registry token through the supported environment mechanism, never a committed literal.
Browser configurationOnly deliberately public values belong in VITE_ settings; no server credentials or evidence tokens.

Release checklist

  1. Identify exact parent/submodule/package revisions and intended deployment topology.
  2. Run builds and meaningful owning-service tests; resolve tracked release blockers and record exceptions explicitly.
  3. Rehearse additive migrations on representative restored fixtures; verify constraints and balance/row reconciliation.
  4. Back up data and immutable evidence; identify application rollback and data-forward-recovery boundaries.
  5. Apply migrations in the release step, not an untrusted preview build; deploy compatible services/consumers.
  6. Smoke-test authentication, tenant isolation, intake/review, financial states and provider failure handling in staging.
  7. Record release evidence and accountable approval; monitor jobs, reconciliation exceptions and external-provider outcomes.

Incident and recovery actions

SymptomInitial response
Job interrupted / provider timeoutInspect persisted job/execution/artifacts; do not blindly replay side effects. Current worker marks interrupted jobs failed for explicit review.
Email send outcome uncertainReconcile provider/SMTP evidence before retrying; successful request acceptance does not prove delivery.
Payment or funding outcome uncertainLook up the persisted operation and provider reference; reconcile before any retry that could create another obligation.
Stale quote/workbench/versionRefresh and review the exact active revision; preserve historical snapshots instead of overwriting.
Database restore / cross-service mismatchRestore evidence and version references, then reconcile parties/currencies/operations across services before financial writes resume.

Documentation maintenance checklist

  • Update the relevant child page and source references when a service contract, schema, calculation or workflow changes.
  • Distinguish local verification, staging evidence and production results with dates and exact scope.
  • Link new defects/gaps to the correct Jira epic; preserve evidence when closing them.
  • Review stale assumptions around authentication, pipeline automation and binding: older repository documents describe superseded behavior.
