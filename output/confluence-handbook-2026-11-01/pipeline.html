Automatic and manual execution

The documented worker scans committed submissions every five seconds and waits fifteen seconds after the latest file before queuing document processing. A finalized ingestion/upload event and at least one file are required. Automatic work follows configured dependencies through schema generation. Organizations, or independent users for their own submissions, can disable automatic document processing; manual advance/rerun remains available.

Jobs and failure semantics

Advance/rerun requests return HTTP 202 with a job. PostgreSQL stores queued/running/completed/failed states; locks and a partial unique index coordinate one active job per submission. A running job interrupted after its execution lock disappears is marked failed, not blindly replayed, because stage work can be partially persisted. Review the failed execution and explicitly rerun where appropriate.

Human corrections and replay

Feedback stores full append-only snapshots, actor/time, expected version, parent and original execution. A restore appends a new version. New pipeline runs do not overwrite an existing human workbench. Organization picklist publication and feedback commits use separate service transactions; a partial failure may require reconciliation rather than rerunning the whole action.

Completion work

Align canonical, workbench and model revisions; retain field-level money/party provenance; implement searchable artifacts and scalable projections. Preserve {ok:false} stage failures and lineage rather than replacing them with successful empty results.
