Recommended implementation order

  1. Agree party/account, currency and revision semantics with AIN-34, AIN-35 and AIN-18; produce the ownership map first.
  2. Add typed references/constraints and validated extension schemas without breaking existing readers.
  3. Implement version/event handoff contracts with domain workflow owners.
  4. Backfill representative legacy records using reviewed mappings; retain unresolved values instead of fabricated defaults.
  5. Build/rebuild projections and measure query plans at agreed loads.
  6. Validate migration, application compatibility, financial reconciliation and rollback before production cutover.

Acceptance boundaries

A schema task is not complete merely because a migration applies. It must demonstrate valid historical records remain readable; invalid direct writes are rejected; same-tenant references hold; duplicated operations cannot double-post; projected balances can be rebuilt; and financial totals reconcile by party/currency. Separate-service references need explicit contract validation rather than impossible cross-database foreign keys.
