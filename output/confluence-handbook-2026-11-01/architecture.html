System shape

The parent workspace coordinates independent repositories/submodules. EnsuredUI hosts the user-facing application and built microfrontends. EnsuredAuth/gateway establishes identity; EnsuredAPI owns marketplace/business workflows and orchestrates supporting services. Pipeline packages provide stage implementations and shared persistence contracts. Dedicated services retain their own identity, KYC, feedback, network or connector responsibilities.

Primary request and data flow

  1. Browser requests reach the configured public gateway and UI origin.
  2. Accounts verify the session; the gateway forwards short-lived request-bound assertions to the intended service.
  3. The owning service checks role, organization, record access and operation policy.
  4. Document operations persist job/execution/artifact history; human edits create separate feedback versions.
  5. Approved workflows freeze snapshots and produce commercial/financial records; external integrations require explicit completion and reconciliation semantics.

Persistence boundaries

Shared local PostgreSQL infrastructure does not imply a shared ownership model. Identity and KYC have separate logical databases; Network owns its records; Feedback owns its schema and version history. API/pipeline data and commercial SQL migrations coexist in the marketplace boundary. Services should communicate through contracts rather than reading each other’s private tables.

Composition and deployment

Marketplace and Network frontends are consumed as built packages in the host. Updating a microfrontend requires rebuilding the host; this is not runtime module federation. Auth supports combined Worker and Node configurations as well as older separate processes. Deployment configuration must identify which supported topology is actually used.

Architecture changes in progress

AIN-47 formalizes ownership, relationship integrity and schema contracts. AIN-52 defines reliable cross-service event handoffs; AIN-53 defines rebuildable read projections. These planned additions must preserve existing API and audit behavior.
