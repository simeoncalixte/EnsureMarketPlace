# Pipeline Process Transformation Reports

This folder contains before/after JSON artifacts generated by the pipeline process tests.
Each report captures the input payload before a process runs and the returned or persisted
shape after that process completes.

## Report Format

Each JSON file follows this shape:

```json
{
  "process": "classification",
  "generatedAt": "2026-05-28T...",
  "transformationCount": 1,
  "transformations": [
    {
      "process": "classification",
      "stage": "classification",
      "testName": "pure classifier maps hurricane submissions to catastrophe property windstorm",
      "description": "Extracted submission text is classified into line of business and subtype.",
      "before": {},
      "after": {},
      "recordedAt": "2026-05-28T..."
    }
  ]
}
```

## Process Reports

| Report | Package / Module | Operation Exercised | What the Transformation Shows |
| --- | --- | --- | --- |
| `ingestion.json` | `src/pipeline/ingestion/route.ts` and `IngestionService` | `POST /api/pipeline/ingestion/process` | Incoming ingestion request payload becomes an ingestion service response. |
| `ingestion-amqp.json` | `src/pipeline/ingestion/service.ts` with mocked `connectors/amqp` | `startAmqpListenerForChannel`, AMQP handler, retry/DLQ handling | Queue messages are converted into channel-tagged ingestion calls; failed deliveries become retry and dead-letter publishes. |
| `ocr.json` | `src/pipeline/ocr/route.ts` and `OcrService` | `POST /api/pipeline/ocr/process` | OCR validates the payload boundary before file reads; incomplete payloads return a missing-submission result. |
| `classification.json` | `src/pipeline/classification/service.ts` | `classifySubmissionLineOfBusiness` | Extracted text is classified into line of business, subtype, confidence, evidence, alternatives, and review status. |
| `extraction.json` | `src/pipeline/extraction/route.ts` and `ExtractionService` | `POST /api/pipeline/extraction/process` | OCR text becomes structured risk fields such as risk type, limit, deductible, effective date, expected yield, and oracle source. |
| `normalization.json` | `src/pipeline/normalization/route.ts` and `NormalizationService` | `POST /api/pipeline/normalization/process` | Structured extraction output is shaped into the normalized data object used downstream. |
| `validation.json` | `src/pipeline/validation/route.ts` and `ValidationService` | `POST /api/pipeline/validation/process` | Normalized/extracted data becomes a validation decision with quality score, missing fields, scrub findings, and reasons. |
| `preRating.json` | `src/pipeline/preRating/service.ts` and `PreRatingService` | `PreRatingService.process` | Validated risk data becomes a score, grade, priority rank, expected yield, and rating reasons. |
| `capacity.json` | `src/pipeline/capacity/service.ts` and `CapacityMatchService` | `CapacityMatchService.process` | Rated risks are matched to open capacity and routed to `priority_queue`, `standard_queue`, or `partner_pool`. |
| `oracleAttestation.json` | `src/pipeline/oracleAttestation/service.ts` and `OracleAttestationService` | `OracleAttestationService.process` | Trigger type and oracle source data become smart-contract readiness decisions with compatibility reasons. |
| `workflow.json` | `src/pipeline/workflow/route.ts` and `WorkflowService` | `POST /api/pipeline/workflow/process` | Validation, rating, oracle, and capacity outputs become a workflow decision, queue, grade, score, and suggested submission status. |
| `storageSearch.json` | `src/pipeline/storageSearch/route.ts` and `StorageSearchService` | `POST /api/pipeline/storage-search/process` | Completed pipeline payload is handed to storage/search and returned as the received envelope. |

## Full Base Lifecycle Artifact

The full parent lifecycle before/after report is generated separately at:

```text
../base-pipeline-transformations.json
```

That file follows one submission through the full base pipeline:

1. Queue ingestion
2. Ingestion
3. OCR
4. Classification
5. Extraction
6. Normalization
7. Validation
8. Pre-rating
9. Capacity match
10. Oracle attestation
11. Workflow
12. Storage/search

## Regenerating Reports

Run the pipeline tests:

```bash
npm --prefix EnsuredAPI test -- src/pipeline --runInBand
```

The JSON reports are written by `test/helpers/pipelineTransformations.ts`.
