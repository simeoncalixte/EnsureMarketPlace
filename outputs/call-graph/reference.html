Foundations & components

  

    
Typography
Space Grotesk for titles and metrics; JetBrains Mono for code, labels, and data. Use 26px titles, 13px explanatory text, and 10–11px compact HUD labels.

    
Spacing & surfaces
4px base grid: 4 / 8 / 12 / 16 / 24px. Panels use a 10px radius, 12px padding, a subtle border, and a dark glass surface over #03050C.

    
Component contract
Panel: label, status, content. KPI: label, value, context. Badge: explicit status text with semantic color. Relationship: labeled source → target and cardinality. Lookup: reference key → target key, with resolved or missing status. Timeline: numbered stage, name, and progress.

    
Interaction & accessibility
Use 180ms for control feedback and a visible cyan focus ring. Pair color with text. Space pauses the simulation; Escape closes this guide. Keep reading surfaces still.

  

  
Document processing workflow

  
Ingestion → OCR → Classification → Routing / Orchestration → Fact Finding → Evidence & Confidence Scoring → Normalization → Validation → Vector Processing → RAG Retrieval → UI Generation → Human Review → Approval / Decision → Export / Integration.

  
Processing stages persist results to the central database, evolving the document schema from v1 to v13. RAG Retrieval is a read-only operation at the API tier; it returns context without a database write. Relationship parsing and lookup support Fact Finding. A red rejection pause precedes a slower retry loop that follows Human Review → Normalization → Validation → Vector Processing → RAG Retrieval → UI Generation → Human Review. Approval records a separate decision; Export delivers approved data. All actions are animated mock examples.

  
Submission origins

  
External Excel, DOCX, email, webhook, PDF, scanned image, CSV, XML, web form, cloud storage, SFTP, database export, event stream, and chat sources send a labeled submission into Ingestion every 20 seconds of animation time. Arrivals rotate through all 14 source types, distinguishing file format from delivery channel. New submissions queue while the current record completes its pipeline; its source ID and format remain attached throughout processing. Space pauses both the pipeline and incoming traffic. These are simulated inputs.

  
RAG processing of the submission

  
Validated content becomes chunks and embeddings in the Vector Store. Retrieval supplies relevant chunks and citations to UI Generation. Chunk metadata carries submission ID, current version, source evidence, and access scope. Corrections repeat vector processing and retrieval so superseded chunks are excluded. Vector values remain in the vector store; the document database keeps chunk references and the generated UI’s citations; retrieval itself adds no stored data. This is a visual simulation.

  
Connected API infrastructure

  
Two API servers connect to PostgreSQL above the database. Human Review sits beside the web client in the client tier. Generated UI data travels through API Server 01 → Web Client → Human Review. Rejected edits travel Human Review → Web Client → API Server 01 → retry processing; revised UI data returns through the API and web client. Review database writes and the decision handoff also pass through the API. Web, mobile, and integration clients connect to the API tier; animated traffic shows the client → API → database paths. These are illustrative connections.
